## 二、阶段一：只检查环境，不做安装

先使用 `$shikaka-video-editing-setup`，检查并记录：

1. 操作系统、CPU 架构、当前 Agent 和实际 Skills 目录。
2. Git 是否能正常运行，并报告实际路径和版本。
3. Python 是否为真实解释器而非空的系统商店别名，版本是否不低于 3.10。
4. `uv` 是否存在；如果不存在，当前 video-use 上游是否仍支持其他安装方式。
5. FFmpeg 与 ffprobe 是否都能正常运行，并报告实际路径和版本。
6. 官方 `video-use` Repo 是否存在于稳定位置：
   - Windows：`%USERPROFILE%\Developer\video-use`
   - macOS/Linux：`~/Developer/video-use`
7. 如果 Repo 已存在，使用 Git 命令检查它是否为真正的 worktree，并记录 exact origin、branch 或 detached commit、HEAD 和 `git status --short`。
8. 整个 video-use Repo 是否已注册到当前 Agent 的 Skills 目录；不能只复制 `SKILL.md`，因为工作流需要同级的 `helpers/`。
9. 本次字幕语言所需字体是否存在、来源是否明确、文件是否有效，并实际验证“食卡卡”字形。
10. 只有本次要保留口播时，才检查 ElevenLabs 凭证来源是否存在；不得显示、读取或推测凭证内容。
11. 只有我要求可编辑剪映草稿时，才检查 `jianying-editor` skill 和剪映草稿目录。
12. 只有我要求 Web 动画时，才检查 Node.js 和对应动画引擎；不要默认安装所有动画工具。

环境检查阶段不得：

- 安装、更新或卸载软件；
- Clone、pull、reset、重写 remote 或修改现有 Repo；
- 下载或覆盖字体；
- 创建 symlink、junction 或改动 Skills 目录；
- 创建或修改凭证文件；
- 上传、转写、剪辑或渲染任何素材。

检查完成后，按以下能力分别报告：

- 基础剪辑：`ready／not ready`
- 中文字幕：`ready／not ready／not requested`
- 语音转写：`ready／not ready／not requested`

## 六、阶段五：素材检查与故事整理

使用 `$shikaka-video-editor`：

1. 用 ffprobe 记录每个素材的 streams、时长、尺寸、帧率、旋转信息、色彩信息、音频和可解码状态。
2. 原素材保持不变；新产物放到素材旁的 `edit/`，或我明确指定的目录。
3. 生成联系表或代表画面，找出食物、手机入画、拍照/扫描、识别结果、加入饮食记录、每日营养和品牌结尾等候选片段。
4. 把观察结果写入 `story-map.md`；它只是候选画面，不是已经批准的剪辑点。
5. 不得复用历史项目里的硬编码路径、时间码、热量值、音乐、日期或旧产品名。
6. 检查素材中是否出现通知、账号、位置、面孔、健康信息或其他隐私内容。

如果原声静音且没有口播用于成片，跳过语音转写，记录：

- `transcription: not_required`
- `source_audio: muted` 或 `unused`
- `cloud_upload: false`

如果要保留口播，在第一次上传前必须告诉我具体文件名、上传到哪个服务、用于什么、可能消耗的额度或费用，并等待我对这次上传的单独确认。

## 八、阶段七：剪辑、字幕和完整预览

策略确认后：

1. 建立 `edl.json`，每段记录 source、source start/end、output start/end、beat、reason、caption 和 audio decision。
2. 每段独立抽取、处理和验证后再拼接。
3. 默认使用干净硬切；只有确实改善理解并已获批准时才使用转场。
4. 开头优先使用清楚的完整食物画面，不要误留空盘或准备动作。
5. 删除无信息价值的识别等待，但保证扫描动作完整，结果停留足够阅读。
6. 图像和功能路径锁定后再加字幕；字幕是最后的画面操作。
7. 中文字幕必须完成字形测试；英文字幕延续批准的 Poppins Bold 风格。
8. 配乐只能使用我提供或已确认授权的来源，精确裁到时间线，并处理开头和结尾淡化。
9. 输出一支包含全部批准画面、字幕和声音的 720×1280 完整预览。

预览必须检查实际渲染文件，而不是只检查命令或时间线：

- 每个剪接点前后是否有跳帧、黑帧、重复帧、闪烁、爆音或动作缺失；
- 食物、手机、识别结果、饮食记录和营养页面是否完整可读；
- 字幕是否正确、没有缺字，并位于平台安全区；
- 是否残留旧产品名、旧日期或历史项目文案；
- 音乐是否削波、突然开始或突然结束；
- streams、时长、尺寸、帧率以及完整解码是否通过。

只有证据指向明确问题时才能自动修正，最多三轮。完成预览 QA 后把完整预览交给我确认，不要把预览称为正式成片。

## 九、阶段八：正式成片与剪映草稿

只有我确认预览，或者我在最初需求中明确预批准了从已确认策略直接导出时，才继续：

1. 输出一支 1080×1920 的正式 `final.mp4`。
2. 对正式文件本身重新检查所有剪接边界、代表画面、字幕、隐私、音画同步、streams、时长和完整解码。
3. 不得用预览 QA 代替正式文件 QA。
4. 如果需要剪映草稿，先读取 `jianying-editor` skill，把业务脚本写在当前项目而不是 Skill 安装目录。
5. 剪映工程使用唯一名称，不覆盖已有草稿；建立独立的视频、配乐和可编辑文字轨道，并验证草稿目录与工程文件。
6. 剪映草稿存在不代表 MP4 已输出；MP4 存在也不代表草稿可编辑。分别回报证据。
